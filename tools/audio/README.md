# tools/audio

The music and the sound effects of POLARITY SHIFT are **generated by code, not recorded**. The files in `assets/audio` are the output of the two commands below; the scripts are the source.

Needs Python 3.12 with `numpy`, `scipy` and `soundfile`. `ffmpeg` is optional (used for the `.ogg` encoder and for the listening previews). The generated audio is already in `assets/audio`, so none of this is needed to build or play the game.

## Commands

```
python tools/audio/build_sfx.py --check            # render and measure every effect, compare the pack with the engine's table (GameAudio.cpp)
python tools/audio/build_sfx.py                    # write assets/audio/se   (62 sounds, 93 files, about 30 s)
python tools/audio/build_sfx.py cursor decide      # only these sounds
python tools/audio/build_sfx.py --preview out.mp3  # also write one listening file with every sound, and out_index.txt (where each one starts)

python tools/audio/build_bgm.py --check            # analyse every score: ranges, density, clashes between voices
python tools/audio/build_bgm.py                    # write assets/audio/bgm  (9 tracks, about 8 minutes)
python tools/audio/build_bgm.py stage_a title      # only these tracks
python tools/audio/build_bgm.py --wav              # also write a stereo preview mix of each track
```

The C++ tests of the audio system are in this folder too: `test_audio_logic.cpp` and `test_heat_floor.cpp` (the plain-C++ logic of the engine; `make -C tools audio-test`), and `engine_test/` (the real `GameAudio.cpp` against a mock of XAudio2; see `engine_test/build.sh`).

## The rules the sound follows

1. **One motto.** A three-note figure (A A D) is the theme of the whole game. It is not repeated, it is transformed: stretched to twice the length (the title), turned upside down (the red face of every track), moved off the beat (stage B), cut into fragments that two faces pass to each other (stage C), played twice as fast (the peak of stage C), put in another mode (the boss is the same theme with the sixth lowered, the clear is the same notes in the major).
2. **One palette.** Every pitched effect uses D, E, G, A or C: the notes that all the keys of the music have in common. An effect is never a wrong note against the score, whatever the music is playing. The chain of absorbs climbs exactly these notes (`AudioLogic::ChainSemitones`).
3. **Two faces.** Blue is glass: a clean sine on top, bars and bells that ring, a soft attack, a long room. Red is ink: a hard attack, brass and wood, no tail. The interface is both at once.
4. **Combat sounds are not mallets.** A hit, a shield and a kill are made of the same layers heard at different sizes (`sfx/common.py: impact`): a snap of noise, a body that falls in pitch, a bolt, a breath of air, a few chips of debris. A shield has no ring: it says "nothing happened". A kill opens the hit.
5. **Alerts live where the music does not.** Warnings are pure, hard-edged tones between 1.5 and 5 kHz plus a sub below 100 Hz, so they are heard through any mix without being louder than it. Warnings are tones (they mean something); damage and destruction are noise and body (they are something).
6. **Levels are measured, not guessed.** Every sound has a class (`LEVELS` in `build_sfx.py`: tick, shot, hit, kill, jingle, alert ...). The A-weighted loudness of the loud part of each file is set per class, so the engine plays everything at 0 dB and the balance of the pack is in the files. A sound that would peak too high is soft-clipped, not turned down.

## Layout

```
build_sfx.py       the command for the effects; the levels, the tails and the check against the engine
sfx/
  registry.py      @sfx(name, class, variants): a recipe registers itself here
  dsp.py           the instruments: glass, bell, pluck, brass, choir, noise, sweeps, zap, thump, crackle, rooms
  common.py        shared helpers (impact, run)
  analysis.py      measurements: A-weighted level, band shares, tonality, dissonance
  ui.py  ship.py  combat.py  boss.py  flow.py     the recipes (62 sounds)

build_bgm.py       the command for the music
bgm6/
  theme.py         the motto, its transformations (augment, mirror, displace ...), keys and chords, voice leading
  arrange.py       tools of an arranger: lead, pads, bass lines, arpeggios, drum patterns
  synth.py         the instruments (physical models: strings, harp, piano, flute, brass, choir, drums)
  render.py        notes -> stems (humanised, panned, put in a room), levels and the .ogg files
  score.py         the nine tracks as code
  check.py         the analysis behind `--check`
```

## Adding a sound

1. Write a recipe in the module that fits (`@sfx("name", "class", variants)`; the function gets a random generator and the number of the variant and returns a mono array).
2. Add the sound to the table of the engine: the `GameSound` enum (`src/core/GameAudio.h`), the `SOUNDS` table (`src/core/GameAudio.cpp`) and the bus (`src/core/AudioMap.h`).
3. `python tools/audio/build_sfx.py --check` compares the pack with the table and prints `MISSING` or `VARIANTS differ` if the two disagree.
4. `python tools/audio/build_sfx.py name` writes the files.
